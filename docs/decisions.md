# Decision log

Short entries, in two tables. **Status:** `decided` | `soft` (expected, revisit if needed). The log
holds every active decision in as few rows as reasonable (D-072 (g)).

- **High-impact:** decisions that shape what a use case gets or must do: scope, outputs and
  artifacts, ML correctness, the lifecycle, compatibility, responsibilities. Costly to reverse; the
  LDS reads these in full.
- **Low-impact:** working rules, tooling, docs, dev-only data, defaults and naming. Cheap to reverse;
  the LDS samples them.

**Rules**
- A new decision gets a new ID in one of the two tables; the table is chosen by impact, as above.
- New information heavily adjacent to a set decision **extends its row** in place; the status notes
  the date and what was extended.
- A superseding decision **replaces the original row in place**: same ID, new text; the status notes
  the date and, in one clause, what it replaced. No superseded rows are kept. If the change matters
  to the history, `docs/UPDATES.md` or `worknotes/log.md` records it.
- Two rows that say the same thing are merged into the lower ID; the status names the IDs it
  absorbed, and every reference is remapped in the same change.

The log was compacted on 2026-10-22 from 128 rows to 58; the old → new mapping is in
`worknotes/log.md` (entry of that date). Decisions still to be made are open decisions (OD-nn) in
`docs/roadmap.md`.

| D-029 | Target Factory and targets.
